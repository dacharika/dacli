# dacli builds dacli

Current development uses the coding host's native agents and tools. The owner
assigns a bounded task and isolated checkout, reviews exact-source evidence and
controls acceptance and landing. dacli no longer launches a wrapped coding CLI.

## Current evidence

The [native plugin](../plugins/codex/README.md) has an actual isolated Codex
app-server smoke receipt for discovery, identity, task reads, attempts, leases,
committed revisions, self-reports and owner revocation. That fixture does not
invoke a model turn. The [native probe report](CODEX_GOVERNANCE_PROBE.md) separately
records measured root/child actions under one installed host version.

These observations do not certify a shared connection as separate child
credentials, a self-report as trusted verification, or a role label as independent
review. The selected harness owns agent execution. Owner-issued native grants
establish the narrower runner and reviewer provenance boundaries.

## Structured delivery and history

Structured delivery evidence includes exact commit/tree observations and retained
command artifacts. Legacy `independent-review-result/v1` records remain readable;
new native review proposals use independent eligible credential families and
current canonical policy. Neither kind should be accepted by merely reporting
that a test command exited zero when its filter matched no tests.

The former empty-repository shell-agent launcher fixture has been removed with
its launch implementation. Historical results remain in Git history and retained
receipts; they are not instructions to run deleted commands. The current plugin
smoke lives at `plugins/codex/scripts/smoke.py` and documents its own explicit
binary, isolated environment and public-fixture requirements.

## Acceptance and cleanup

Worktree tests must run against that worktree's actual source. Record the source,
working directory, test names, output and digest before owner acceptance. A
contributor cannot independently review their own change. Changes in a shared
main checkout are not evidence for a different task branch.

Use explicit task/VCS commands to record reviewed delivery and landing. Preserve
historical transcripts, attribution, projection and verification receipts. Preview
cleanup, then apply only the exact safe plan; retained bytes and recovery guards
are part of the evidence contract. See the [operator playbook](OPERATOR_PLAYBOOK.md).

# Native canonical acceptance

Native acceptance consumes stored verification and review producers. An asserted
role name, a successful shell transcript, or a shared MCP identity is not an
independent review. The runner and reviewer authenticate separately, and the
reviewer must have an owner-issued task/repository grant and no implementation
history or capabilities in the implementing family. This remains cooperative
credential separation, not host confinement or cryptographic process identity.

The owner explicitly upgrades a disposable or deliberately selected authority
from schema13 to14:

```
dacli native acceptance upgrade --config /private/owner.json
```

Migration initializes the acceptance operation and task retirement maps while
preserving existing preflight, checkpoint, budget, lifecycle, recovery, evidence
and review history. Genuine schema13 writers refuse schema14. Upgrade does not
accept a task or release any protection.

The separately authenticated reviewer exports a current, provenance-bound input:

```
dacli native acceptance candidate --connection /private/reviewer-connection.json --review-config /private/reviewer-profile.json --review REVIEW_ID --json
```

The `candidate.Input` object carries exact authority, task, review, attempt,
revision, original lease/fence, repository, commit, tree, checklist, policy and
candidate digest bindings. The owner supplies a globally unique `OperationKey`
and writes that object to a private request file. Candidate evidence contains
safe producer IDs/digests and authenticated session IDs; it excludes credentials,
private paths and executable command text. Export is an observation, not a permit.

```
dacli accept apply-native --config /private/owner.json --review-policy /private/review-policy.json --request /private/input.json --json
```

Apply repeats independent producer eligibility, exact clean reviewed checkout,
current private policy/checklist and bounded canonical delivery obligations.
The configured local landing branch must genuinely contain the reviewed commit,
and its genuine commit tree must equal the reviewed tree. Git observation strips
ambient overrides, disables replacement objects and bounds time/output. Required
PR/external landing or unsupported delivery slices refuse before canonical effects;
this command does not infer external integration or launch a worker.

A durable `closing` record retires only this task before the first canonical
write. All implementing families, descendants and controllers lose fresh task
execution authority, including a pending runner's completion. Unrelated task
rights remain usable within their original scopes. Existing leases and dispatch
protection remain; owner recovery is a separate explicit decision.

Canonical closure checks all criteria, stamps completion and records the exact
native receipt, then moves the unique task to DONE. `Applied` is returned only
after bounded unique raw-byte readback and durable finalization. Exact operation
replay returns historical success without repeating canonical effects. Changed
keys/payloads, aliases, missing tasks, changed bytes, authority withdrawal and stale
producers do not obtain fresh acceptance.

The two stores are not crash-atomic. A failed save/move/finalization retains the
original operation and closing retirement. An ignored canonical fixture can
continue only with fresh current authority and exact operation-generated bytes.
Tracked canonical partial writes make the reviewed checkout dirty: the supported
boundary is an explicit policy refusal requiring owner reconciliation, with no
`Applied`, no restoration and no new operation key. Already exact DONE receipt
bytes can finalize historical state without a new canonical effect. Filesystem
observations do not freeze arbitrary host writers; isolated cooperative writers
remain required. Legacy spawned-review acceptance keeps its existing guards.

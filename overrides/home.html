Authority, separated

Autonomy works when every participant has one job.

dacli does not replace the orchestrator or the coding agent. It keeps their work inside a process whose claims can be checked after the model session is gone.

A

Agent judgment

The orchestrator interprets goals, decomposes work, and judges evidence. Coding agents implement, test, and review inside their assigned scope.

D

What dacli controls

Authenticated requests, canonical task scope, external attempts, fenced leases, revision evidence and owner-issued decisions. Direct host filesystem actions remain outside these cooperative gates.

H

What stays human

Product direction, credentials, exceptions and release authority. The native host owns agent creation, model choice, sandbox and spending.

Explicit governance boundaries

From the next critical task to evidence on trunk.

Native operations reauthenticate current authority. A refusal is an answer; unknown evidence fails closed. Native final task acceptance remains future work.

  1. 01
    Plan

    Select work that moves the critical path

    Dependencies, slack, priority, capacity, and path claims determine the ready frontier.

  2. 02
    Execute

    Isolate workers before they write

    The host creates agents and isolated checkouts. Scoped attempts and fenced leases coordinate operations through the governance interface.

  3. 03
    Verify

    Run the contracts that changed

    Record actual checks against the exact source. Self-reports are assertions; trusted runner evidence needs an owner-issued grant.

  4. 04
    Review

    Exact-tree review, not a generic approval

    Independent native review requires eligible credential families, owner grants and exact revision evidence. A shared MCP connection shares one identity.

  5. 05
    Land

    Observe GitHub before recording completion

    The owner inspects checks, reviews and fresh trunk evidence. Native publication decisions do not publish, merge or accept tasks themselves.

The record stays visible

Operate the swarm from evidence, not chat history.

The dashboard projects canonical tasks and retained delivery evidence. Historical loop, routing and usage panels remain readable for audit; they are not a native session monitor or current execution authority.

  • Explain every recommendation. Rank, rejected routes, claims, freshness, and the next safe action stay attached.
  • Recover without guessing. Retained journals, handoffs and exact remote identities support conservative recovery and archival.
  • Measure improvement honestly. Adjacent windows retain sample size, task-size context, coverage, and exact drill-down evidence; missing cost stays unknown.
  • Publish the minimum. Public-safe task fields are the default for public repositories; internal evidence needs recorded authority and `--include-internal`.

Boundaries worth asking about

The safe default is explicit.

Does dacli switch coding CLIs when one fails?

No. Coding-agent launchers and runtime adapters have been removed. Codex is the first measured native plugin integration; other hosts need their own conformance evidence.

Does it publish internal findings to GitHub?

Not by default. Public repositories receive the typed public-safe projection. Internal findings, decisions, and verdicts need separate repository authority and an explicit request.

Can it run forever?

Repeated work belongs to the native host. dacli has no provider-driven loop or service supervisor. Every governance transition still needs current authority and evidence.

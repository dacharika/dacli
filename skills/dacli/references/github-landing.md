# Explicit landing

Preview github pull <project> --dry-run and github projection before authorized writes. Use exact task/PR bindings and inspect pr diagnose --task <ref> --json. Observe both merged PR and the commit on configured trunk before owner acceptance or issue closure when PR landing is required. Native decision consumption is not external publication. Use retained individual PR/integration commands under their existing guards; do not bypass them with a guessed merge sequence.

See the [operator playbook](https://github.com/dacharika/dacli/blob/main/docs/OPERATOR_PLAYBOOK.md) and inspect `dacli capabilities --json` for the installed surface.

Land independently ready features separately. Preserve each feature's exact candidate, complete required checks and independent review; a shared QA queue does not transfer evidence. An unrelated blocked feature does not prevent an otherwise authorized reviewed merge. Honor the user's CI trigger policy.

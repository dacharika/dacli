# Roles and authority

Role files describe scope, skills, escalation and intended responsibilities. They help the host plan work but do not authenticate native principals. Runtime/model fields in historical roles do not select a provider process. Independent reviewers need eligible credential families, owner grants and exact revision evidence, not merely another role name.

See the [operator playbook](https://github.com/dacharika/dacli/blob/main/docs/OPERATOR_PLAYBOOK.md) and inspect `dacli capabilities --json` for the installed surface.

Assign separate independent features to implementation lanes, with focused acceptance and disjoint path claims. Keep a reviewer and an integration/QA coordinator available; do not use all observed host slots for writers or infer a fixed concurrency limit from a roster. One shared MCP principal cannot review itself under another label.
